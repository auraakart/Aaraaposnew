# V2.17 — Android Build & Reproducibility Foundation

## Purpose

V2.17 closes the repository-only Android/build reproducibility gaps explicitly deferred in V2.10.

The milestone adds a real Android platform scaffold generated by the same Flutter toolchain used in CI, commits dependency lockfiles, and makes a debug APK compile part of every pull-request quality gate.

## Trusted generation source

The initial platform files were generated in GitHub Actions using:

- Flutter stable 3.47.5
- `flutter create --platforms=android --project-name aaraapos_pos --org com.auraakart .`
- `flutter pub get`
- Node 22
- `npm install --package-lock-only`

Generated files were captured byte-for-byte from the CI runner and committed through Git objects.

Machine-specific/generated-ignored files were deliberately excluded:
- `android/local.properties`
- Android Studio `.iml`
- `GeneratedPluginRegistrant.java`
- generated Gradle wrapper scripts/JAR

The generated Android `.gitignore` remains authoritative for those files.

## Committed reproducibility artifacts

### API
- `services/api/package-lock.json`

### Flutter
- `apps/pos_mobile/pubspec.lock`
- `apps/pos_mobile/.metadata`

### Android
Portable Gradle/app/resource/manifest scaffold under:
- `apps/pos_mobile/android/`

The Android launcher label is `AaraaPOS`.

## Pinned toolchain

CI now pins Flutter to:

`3.47.5`

This matches the committed Flutter `.metadata` generation version.

Node remains pinned to major version 22 in CI.

## Reproducible installs

API CI now uses:

`npm ci --no-audit --no-fund`

instead of a mutable `npm install`.

Flutter CI now uses:

`flutter pub get --enforce-lockfile`

so dependency resolution must agree with the committed `pubspec.lock`.

## Android compile gate

Every normal mobile CI run now performs:

1. locked dependency restore
2. static analysis
3. Flutter tests
4. `flutter build apk --debug --no-pub`

This is a real Android compile gate, not a documentation-only readiness claim.

The generated APK is a CI validation output; V2.17 does not publish or distribute it.

## Repository policy

The repository policy now fails if any of the following disappear:

- API package lock
- Flutter pub lock
- Flutter metadata
- Android settings Gradle file
- Android app Gradle file
- Android main manifest

This prevents accidental regression to a source-only Flutter package that cannot prove Android buildability.

## Application identity boundary

The generated debug scaffold currently uses the generated namespace/application ID derived from:

- organization: `com.auraakart`
- project: `aaraapos_pos`

V2.17 does not declare that generated identifier to be the final production Play Store application ID.

Final production package identity must be frozen before first external store release because application IDs are difficult to change after distribution.

## Signing boundary

The generated Flutter Android template uses debug signing for the release build type placeholder, exactly as generated by Flutter.

This is **not production signing**.

Before production distribution, AaraaPOS still requires:
- dedicated release keystore
- protected signing credentials
- CI secret handling
- release signing configuration
- store package identity freeze
- Play Console setup
- release artifact provenance
- physical-device validation

## Definition of done

V2.17 is complete only when the exact PR head passes:

- repository policy
- npm vulnerability audit
- TypeScript typecheck/tests
- locked Flutter dependency resolution
- Flutter analysis/tests
- Android debug APK compile
- foundation baseline gate

## Not claimed

V2.17 does not claim:
- signed production APK/AAB
- Play Store readiness
- production package identity finalization
- physical-device certification
- hardware peripheral validation
- release keystore management
- production rollout or monitoring
